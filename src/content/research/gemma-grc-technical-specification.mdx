This is the reference document for Gemma GRC: what each part does, how data moves between the parts, and the evidence behind each design choice. The story of how it got here is in [It Learned How I Sound, Not What I Know](/posts/it-learned-how-i-sound) and [The Law Moved in July](/posts/the-law-moved-in-july). The run-by-run lab record is in [When the Instrument Is the Bottleneck](/research/when-the-instrument-is-the-bottleneck). This document is versioned, and when a number changes, the version changes with it.

## At a glance

| Part | Summary |
|---|---|
| What it is | A question-answering assistant for GRC work that answers only from a governed library and cites every claim |
| Where it runs | A Mac Mini M4 with 24 GB of memory, with no network connection at question time |
| Generator | Gemma 3 4B instruct, 4-bit, on Apple's MLX, greedy decoding, no fine-tuned adapter |
| Library | 5,989 chunks from 58 official public sources in six lanes, plus 315 chunks of my own writing and teaching |
| Retrieval | BM25 and BGE-small embeddings fused by reciprocal rank, top eight, with a router for questions about when rules apply |
| Agent access | One owner-only MCP tool that returns text for public and own passages and counts for everything else |
| Evaluation | 564 questions: 457 answerable, 99 whose answer is not in the library, 8 canaries |
| Judges | Rules, then FactCG claim by claim, both tested on 272 controls before use |
| Baseline | 82% of claims supported by a right passage, against 23% from memory; 56% of questions the library cannot answer are refused (Run 011) |
| Status | Working system; Run 011 is provisional until the test set is frozen |

## Design principles

1. **Read, don't remember.** Facts live in the library, where they can be updated in an evening and checked in a minute. The model supplies language and discipline, not facts. When I fine-tuned a small model on my notes, fabricated details rose from one answer in five to nearly half.
2. **Show me the page.** Every factual claim cites a passage the model was shown. When the library does not cover a question, the answer says what is missing and where it would be.
3. **Govern what goes in.** A fail-closed gate decides what enters the library. Every passage records where it came from and what its license allows, and its provenance class decides where its text may go.
4. **Label everything.** Every regulatory passage carries its citation, version date, application date and status: in force, draft or superseded. Superseded texts stay in the library, labeled, because "what did this replace?" is a common question.
5. **Test the instruments.** Retrievers, judges and the test set are measured before anything is measured with them.
6. **The model is replaceable.** Because the knowledge lives in the library, swapping the generator is a configuration change followed by a rerun of the tests.
7. **Local by default.** Answers are produced on the Mac. Text leaves the machine only when its provenance class allows it.

The fetcher accepts only the official hosts of the issuing bodies: the EU institutions and agencies, the UK government, legislation.gov.uk and the UK regulators, the US banking agencies, and NIST, including NIST's own GitHub organization for the OSCAL catalogs. It follows redirects itself, forcing https and checking the host again on every hop, and refuses anything else.

EUR-Lex answers scripts with a bot challenge: an HTTP 202 and an empty body. The fetcher never tries to get past it. EU acts come instead from the Publications Office's CELLAR repository, requested by CELEX number with content negotiation for XHTML.

Every raw file is hashed with sha256 and logged with its retrieval date, so any passage can be traced to the exact bytes it came from.

### Parsing and labels

| Format | Sources | Unit |
|---|---|---|
| EUR-Lex XHTML | 13 EU acts, original and consolidated | Article, recital or annex, with consolidation markers removed |
| UK CLML XML | 2 instruments from legislation.gov.uk | Regulation or section |
| OSCAL JSON | 4 NIST catalogs | Control or enhancement |
| CPRT JSON | The NIST AI RMF | Subcategory |
| PDF | 31 guidance documents, statements and rules | Page, with running headers and front matter removed |
| HTML | 7 letters, bulletins and web pages | The document body |

Units are packed into chunks of at most 1,700 characters of body text. Each chunk starts with a header that carries its citation and labels, so the label travels with the text into the prompt:

```text
SR 11-7 guidance p. 8: III. OVERVIEW OF MODEL RISK MANAGEMENT (part 3 of 3)
SR 11-7 / OCC Bulletin 2011-12 attachment | version 2011-04-04 | [SUPERSEDED by SR 26-2 (17 Apr 2026); kept for history]
```

Drafts carry `[DRAFT: not adopted; do not state it as law]`. Each chunk also stores structured fields: a content-hash ID, provenance, jurisdiction, instrument, status, version date, application date, license, whether it may train a model, official URL, retrieval date, document, unit and formal citation.

### My notes

Notes and course material from my vault pass the gate described on the [project page](/projects/gemma-grc). A note is held back if it has a classification, sensitivity or handling label other than public, a classification line at the top, a private or confidential flag or tag, or a handling banner. Quirks in line endings or frontmatter cannot open the gate. Cleared notes are chunked, PII is redacted, and each chunk is stamped with a content-hash ID and a provenance class: own, for my own writing and teaching, or a class that stays local.

The provenance class decides which build a chunk joins.

- **The clean build** holds public texts and my own writing: 6,304 chunks. It is the only build used for evaluation, examples and anything published, and it is indexed with the stock BGE-small model.
- **The local build** adds every other class the gate clears, for 7,167 chunks. It serves my own questions on the Mac, with the search model I fine-tuned in August. That model was trained before the gate existed, so it never leaves the machine.

Each index is stamped with fingerprints of its corpus and its embedding model, and it refuses to load against anything else. Chunk IDs are content hashes, so a passage keeps its ID across rebuilds unless its text changes.

### Hybrid retrieval

The question is ranked two ways: BM25 over the chunk text, and cosine similarity over BGE-small embeddings, with BGE's query instruction added to the front of the question. The two rankings are merged by reciprocal rank fusion with the usual constant of 60, and the top eight passages are kept. There is no reranker; one made results worse when I tried it.

### Temporal routing

Questions about when a rule applies were the weakest category. Asked when the Annex III obligations of the AI Act apply, the search ranked the Act's descriptive articles highly and never surfaced Article 113, the article that sets the dates. The model then supplied a stale date and cited passages that contained none.

The router is a narrow fix for that failure. When a question asks when something applies, enters into force or takes effect, the router works out which instrument it means: by name, through aliases in the manifest, or else as the document that dominates the top 20 results. It then puts up to two of that instrument's application provisions first, meaning the articles headed entry into force, application, commencement, transposition or transitional provisions. Everything else keeps its fused order.

| Question set | Right passage in the top eight, before | After |
|---|---|---|
| Canaries | 6 of 8 | 8 of 8 |
| Temporal probes | 6 of 10 | 10 of 10 |
| Eval v3 temporal questions | 13 of 13 | 13 of 13 |

The router can be switched off, and Run 011's router-off arm does exactly that.

### Context and prompt

Passages go into the prompt in rank order, each clipped to 2,000 characters, until a 13,000-character budget is used up. Long passages fill the budget early. Across Run 011's 450 questions, 115 prompts held six or seven passages rather than eight. The prompt is short, and its four rules do most of the work:

```text
Rules:
- Cite the context number you used, like [2], for each factual claim.
- If the context does not contain the answer, say exactly what is missing and which document would hold it. Do not guess.
- Never invent article numbers, control IDs, dates, or URLs.
- If a passage is marked [DRAFT], [PROPOSAL] or [SUPERSEDED], say so whenever you rely on it; never present it as current law.
```

### Generation

Gemma 3 4B instruct runs in a 4-bit MLX build with greedy decoding and at most 500 new tokens, so the same question against the same library always gets the same answer. mlx-lm is pinned to a commit that includes the fix for CVE-2026-5843. The model carries no fine-tuned adapter. On an earlier setup, retrieval raised answer quality by 0.86 points on a five-point scale (95% CI 0.48 to 1.24). Fine-tuning on top of retrieval added 0.04 (CI -0.34 to 0.44), which is nothing. After each answer, the tool lists its sources with citation, status, version date and official URL.

### One answer, end to end

A real run from 28 September, on the clean build. The question was: "Our model risk policy still cites SR 11-7. Is that still current, and does the current guidance cover generative AI?"

The search returned eight passages: six pages of SR 11-7, each labeled superseded; one of my lecture notes; and page 3 of the 2026 interagency guidance, which says generative and agentic AI models are not within its scope. The answer said SR 11-7 was superseded by SR 26-2 on 17 April 2026, and cited the label. Its fourth sentence then said the new guidance does cover generative AI, and its fifth said it does not.

FactCG scored each cited sentence against its passage: 0.80, 0.88, 0.20 for the misread, 0.95 and 0.81. The judge caught the one claim a reader should not trust. Asked the same question with no library, the same model said SR 11-7 was still current and dated it to 2019.

## Agent access

My agents reach the library through one MCP tool, `search_grc`, served over stdio on the Mac. It is registered for my own sessions only. My Discord agents get it only on turns I start myself, never on a handoff from one agent to another, and the grant lives outside every repository.

The tool returns passage text only for public texts and my own writing. Matches in any other class come back as counts, so an agent knows something relevant exists and can tell me to look locally. Public passages arrive with their citation, status, version date, official URL and a handling note derived from their license.

This is the one path where library text reaches a model off the machine. The agents run on a hosted model, so only text whose class allows it to leave is ever returned. Answers from `ask.py` never leave the Mac.

Eval v3 is the test set every change is measured against. It is built from the clean build only, so everything about it can be discussed in public.

- **Questions.** qwen2.5 14B wrote questions from sampled units. A deterministic check dropped any question that did not name its instrument or authority, and any about URLs, contact details or page numbers. Of 599 drafted, 564 are usable: 457 answerable, 99 absent (the library does not hold the answer; 35 more were dropped because it did) and 8 canaries.
- **Canaries.** Eight hand-written questions about facts that changed in 2026:
  - the AI Act's new application dates;
  - the new wording of the AI literacy duty in Article 4;
  - when the Commission's fines for general-purpose AI providers became enforceable;
  - the four UK critical third parties;
  - SR 11-7's replacement, and what that replacement leaves out of scope;
  - the Cyber Resilience Act reporting duty that went live on 11 September.

  A system answering from stale memory fails them, so every run includes them, whatever the split.
- **Holdout.** Questions are split by source unit, not by question, so no unit feeds both dev and test. That gives 931 units, 115 dev questions and 449 test questions.
- **Several right answers.** Each question gets a set of gold passages, not just one. Candidates are pooled from four retrievers (BM25, BGE, BGE-M3 and the hybrid) to depth 6, and two local judges grade each for relevance from 0 to 3.
- **Grading the graders.** Claude also grades a pair when both the question and the passage are public: 1,389 pairs, for evaluation only, and never as training data. When the local judges disagreed, Claude sided with qwen2.5 14B 85% of the time, so qwen settles disagreements on the 396 pairs that never leave the Mac.
- **My audit.** I grade a blind sample of 100 pairs, drawn from Claude's grades, the tie-breaks and the jury, with no other grade on screen. When the audit is done, the set is frozen and its sha256 recorded.

Answers are scored claim by claim, on the Mac, by judges from model families other than the generator's.

- **Tier 0: rules.** No model is involved. An answer is split into claims, and openers, sign-offs and headings such as "Here's the answer to your question, based solely on the provided context:" are not claims. Every citation must point at a passage that reached the prompt. Every date, number and article, section or control reference in a claim must appear in the passages it cites, and dates match in any format. Abstentions, including the hedged ("the context does not provide") and closed-book ("I don't have information") kinds, are scored as abstentions.
- **Tier 1: FactCG.** FactCG-DeBERTa-v3-Large (0.4 billion parameters, MIT license) scores whether a passage supports a claim. It needs its authors' instruction template; called as a plain sentence pair, it cannot tell right from wrong. Each claim is checked against its cited passages first, then against every shown passage if those do not support it, then against the gold passages. A score of 0.5 or more counts as support.
- **Tier 2: candidates.** Granite Guardian 4.1 8B (groundedness) and gpt-oss-20b (holistic, on binary criteria) have been tested but are not in use yet.

Before a judge is used, it runs on 272 controls built from the test set, where the right verdict is known:

FactCG gets 269 of 272 right, so it is the claim judge. The rules catch changed details, wrong abstentions and wrong answers, but not added claims or wrong citations. That is expected: they are a cheap first filter.

The two LLM judges failed most quote positives, and the fault is partly in the controls. The quote is the first sentence of the gold passage that carries a date or number, whether or not it answers the question. FactCG ignores the question and passes them, while the LLM judges read the question and call them non-answers. Until the quote controls are rebuilt, Tier 2 stays unused. Granite Guardian also needs its thinking mode on, because without it the model calls everything ungrounded, and it takes about 20 seconds per claim.

The relevance judges were tested the same way, against Claude's grades on 300 pairs. Gemma 4 E4B agreed on 48% (Cohen's kappa 0.14), and qwen2.5 14B on 82% (kappa 0.50). Gemma 4 E4B is being replaced as a juror.

One rule sits above all of this: only open-weight judges from families other than the generator's may drive a training decision. Claude's grades evaluate; they never train.

### Metrics

A claim is a sentence or list item of an answer, after openers, sign-offs and headings are dropped.

| Metric | Definition |
|---|---|
| Correct claims | Share of claims that a gold passage supports |
| Grounded claims | Share of claims that a passage the model was shown supports |
| Citation precision | Share of cited claims whose cited passage supports them |
| Fabrication | Answers with a claim supported by no gold or shown passage, or with a date, number or reference found in none of them |
| Cites unseen | Answers with a bracketed number that is not a passage the model was shown |
| Wrong abstention | Answerable questions the model declined |
| Gold hit | A gold passage among those shown |
| Absent abstention | Questions with no answer in the library that the model correctly declined |
| Canary pass | The answer states the changed fact (a date in any format), does not state the stale one, and does not abstain |

Samples are averaged within a question first, then across questions, with 95% bootstrap intervals. Two runs are compared question by question with a paired bootstrap.

**The library carries the facts.** The same model, asked the bare question with no library, supports 23% of its claims with a right passage and almost never declines. With the library, it supports 82% and declines just over half of the questions it should.

**The router does what it was built for and nothing else.** It moves the date canaries and leaves every other measure where it was, so it stays on.

**"Unsupported" is mostly one sentence.** 276 of 1,086 router-on answers have a claim the judge could not tie to a passage, and 212 of them have exactly one. That claim is usually commentary, an inference, or a sentence about the answer itself. Invented dates, numbers or references are rare: 7 claims in 1,086 answers.

**Answering what the library cannot is the weakest behavior.** 44% of questions whose answer is not in the library still got an answer, assembled from nearby passages.

**Citations are looser than claims.** 63% of cited claims are supported by the passage they cite, though 90% of claims are supported by some passage the model was shown. Of the 90 answers with a bracketed number that is not a shown passage, 83 carry numbers above 8, which are reference markers copied from the source text, such as a NIST document's [154]; 7 point at a passage the context budget cut.

**Canaries: 20 of 24.** Two of three samples said the Commission's fines for general-purpose AI providers apply from 2 February 2025, not 2 August 2026, and two of three said the 2026 model risk guidance covers generative AI.

### Measuring the measurement

The first scoring of Run 011 had faults of its own, found by reading the answers rather than the averages:

- **Openers were judged as claims.** Answers that open with "Here's the answer to your question, based solely on the provided context:" were marked fabricated 63% of the time, against 17% without one.
- **Canary checks were literal.** "July 13, 2026" failed a check for "13 July 2026", italics in "*not* within the scope" failed a correct answer, and an answer that began "Yes, the guidance applies to generative AI" passed because a later sentence quoted the right phrase.
- **The refusal detector was narrow.** It missed "the context does not provide", and its closed-book form, "I don't have information", entirely.

Scorer 2026-10-01.1 fixes all three, and every arm was scored again without generating a single new answer:

| Router on | First scoring (2026-09-29.2) | Rescored (2026-10-01.1) |
|---|---|---|
| Answers with an unsupported claim | 36.0% | 25.4% |
| Canaries passed | 70.8% | 83.3% |
| Refuses when the library has no answer | 44.2% | 56.2% |
| Claims supported by a right passage | 79.2% | 81.6% |

The rescored canary results match a line-by-line read of all 24 answers by Claude, the evaluation-only grader. The first scores are archived beside the new ones, never mixed with them.

Other faults surfaced while the run was live:

- **Before any answer was scored.** The scorer treated a date as unsupported when the passage wrote it in another format, read stray punctuation into amounts, counted a detail that sat in a different shown passage as fabricated rather than as a citation error, and accepted citations to passages the context budget had kept out of the prompt.
- **While generating.** The run stopped at answer 1,057 with a Metal out-of-memory error.
- **While scoring.** The scorer's GPU cache grew to 27 GB, and a bracketed date, "[2026-07-27]", crashed the citation parser.

All were fixed, and two answers generated again after the memory fixes matched the originals word for word.

## Findings so far

| Finding | Evidence | Consequence |
|---|---|---|
| Fine-tuning a small model on my notes taught it my style, not my facts | Fabricated details rose from 20% to 48% on a 1B model and from 26% to 36% on a 4B model | The generator ships without an adapter |
| Retrieval is the largest gain | Plus 0.86 on a five-point scale against closed book (95% CI 0.48 to 1.24) | The library became the product |
| Fine-tuning the search model paid off where fine-tuning the generator did not | The right passage in the top four rose from 71% to 79% after nine minutes of training | Tune the failing component, not the famous one |
| The instruments failed before the model did | A judge that scored 4.99 of 5 on everything, a tokenizer call that hid a NaN, a missing query prefix, and a noise floor of about 0.3 points at 50 questions | Every instrument is control-tested, and the test set has 564 questions, not 50 |
| Date questions failed on retrieval, not reading | Article 113 was not in the top 60 results for "when" questions | The temporal router took the canaries from 6 of 8 to 8 of 8 |
| The generator misreads | It said the 2026 guidance "does cover generative AI" against a passage saying it does not, and FactCG scored the claim 0.20; in Run 011, two of three samples of the scope canary said the same | Claim-level judging decides any generator swap |

## What it is for

### Today

- **"Where exactly does it say that, and is it still current?"** A cited answer in seconds, with the version and status of each source.
- **Regimes side by side.** Incident reporting under DORA and NIS2, or oversight of critical technology providers in the EU and the UK, with both sides cited.
- **Questions whose answer moved.** The AI Act timetable, SR 26-2, the UK designations: maintained text beats memorized text.
- **Finding what is missing.** When it cannot find something, that usually marks knowledge that lives in someone's head. In a compliance function, that is key person risk.
- **A research tool for agents.** My research, content and teaching agents cite primary text through the MCP tool instead of their own recall.

### Not for

- Settling an ambiguous interpretation, predicting how a supervisor will read an answer, or standing in for legal advice. That judgment stays with the professional.
- Confidential or client material on a personal machine. The regulator-response work below belongs in an organization's own environment.

**Policy alignment.** Break a regulation into obligations: who must do what, by when. Match each obligation to the policy clauses that should cover it. Classify each as covered, partially covered, missing or in conflict, with both texts cited side by side. For each gap, draft a revision tied to the obligation it closes.

The draft can be automated; the change cannot, because a policy edit needs an owner, an approval and change control. The error that matters most is a false "covered", so the first metric is precision on "covered" against a hand-labeled set of obligations and clauses.

**Regulator response memory.** Treat every response sent to a supervisor as a guiding document, with its context attached: which regulator, when, the question, the scope, the commitments made and the facts relied on. When a similar question arrives from a different regulator, the assistant would:

1. Find what was said before.
2. Check that the scope really matches.
3. Flag facts that have changed since.
4. Flag anything that would contradict what another regulator was told.
5. Draft, with sources.

Supervisors share information about the providers they both oversee. The ESAs and the UK authorities signed a memorandum of understanding on critical technology providers in January 2026, and it is in lane 2.

This capability does not belong on a personal computer. Responses to supervisors can be confidential supervisory information, which the supervisor controls, and legal should sign off before any of it is indexed. My project stays on public texts and my own notes, and it proves the methods: what goes into the library, how each passage is labeled, and how each capability is tested.

## Known limitations

- **It answers what the library cannot.** In Run 011 it declined only 56% of questions whose answer is not in the library; the rest got an answer assembled from nearby passages. This is the first thing to fix.
- **The generator misreads.** Negation and list scope trip it up. It wrote that the 2026 guidance covers generative AI one sentence before saying it does not. It also wrote that SR 11-7 was superseded "by SR 26-2 and SR 21-8", when SR 26-2 superseded both. In Run 011, two of three samples got the date of the Commission's fines for general-purpose AI providers wrong.
- **Citations are loose.** 63% of cited claims are supported by the passage they cite. 8% of answers carry a bracketed number that is not a passage the model was shown; nearly all are reference markers copied from the source, which a reader could mistake for citations.
- **Eight passages is really six to eight.** The 13,000-character budget cut the prompt to six or seven passages for 115 of 450 questions.
- **Phrasing matters.** BM25 has no stemming, and a question that names an old instrument can pull back only that instrument's pages.
- **It over-answers dates.** Asked about Annex III, the model lists every date in Article 113.
- **The numbers are provisional.** The eval is a draft until the audit, and every result records the hash of the eval it used and the version of the scorer that judged it.
- **One machine, one user.** There is no availability, access control or change management beyond what a personal lab needs, and none of this is legal advice.

### Software

Python 3.12. MLX 0.32.3, with mlx-lm pinned to a commit on its main branch for the CVE-2026-5843 fix. Ollama 0.34.4; since version 0.34, a re-pulled Gemma 4 thinks by default, so every JSON call turns thinking off. FactCG runs on PyTorch with Apple's MPS backend. MLX's buffer cache is capped at 1 GiB and emptied after every answer, and PyTorch's MPS cache is emptied after every FactCG call; without both, Run 011 hit a Metal out-of-memory error and the scorer grew to 27 GB.

### Reproducibility controls

- Chunk IDs are content hashes, and the index refuses to load against a different corpus or embedding model.
- Every raw source file is hashed at fetch time, with its retrieval date.
- The question-answering tool decodes greedily. Evaluation runs pin a seed for every question and sample.
- Every run writes its configuration (model, build, k, router, temperature, eval hash, corpus fingerprint, prompt hash and library versions) and refuses to resume under a different one.
- Every score records the version of the scorer that produced it and the verdict for each claim. Scores from another version are archived, never mixed, and scores are reused across runs only within a version.
- 90 unit tests cover the rules, parsers, router and scoring without loading a model.
