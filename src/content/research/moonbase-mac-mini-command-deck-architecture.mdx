## 1. Scope and architectural motivation

Earlier releases of [Moonbase](/projects/moonbase/) explored two distinct models for a personal agent workspace: a walkable 3D lunar habitat with read-only process telemetry ([Building Moonbase](/posts/building-moonbase/)), and a server-owned 2D control plane built around versioned SDK profiles, workstreams, and explicit consent gates ([Persistent Agent Workbench](/posts/moonbase-persistent-agent-workbench/) and its [technical specification](/research/moonbase-workbench-technical-specification/)).

While the SDK control plane enforced strong isolation guarantees, it introduced two practical failure modes for daily single-owner use on an always-on Mac mini:

1. **Duplicate runtime and authentication friction:** Consumer desktop subscriptions (`Claude.app` and `GitHub Copilot.app`) cannot be freely re-hosted inside third-party SDK harnesses, leaving the SDK-backed Claude route permanently `auth-blocked` while the native desktop apps were already signed in and running on the same host.
2. **Spatial occlusion in the 3D loft:** The original upstairs Flight Director office (`8m x 5m`) suffered from third-person camera collisions against the surrounding glass and south walls, off-center desk monitors, and a hardcoded October seasonal hand mesh (`warlockHand`) that rendered green zombie claws in first-person mode.

The October 17, 2026 release (`PR #20` and `PR #22`, deployed on `https://moonbase.neural-bridge.dev`) resolves both issues by turning the upstairs Flight Director office into a direct remote portal for the live Mac mini host and binding the downstairs mini dinosaur agents to real local session logs. The companion narrative article ([Moonbase: Back to the Drawing Board](/posts/moonbase-back-to-the-drawing-board/)) covers the product rationale; this paper documents the exact runtime contracts, spatial math, and Blender asset pipelines.

## 2. System boundary and end-to-end architecture

Moonbase continues to run as a single-tenant Node and TypeScript service on the Mac mini (`127.0.0.1:47831`), fronted by Cloudflare Access and Moonbase session authentication (`/login` Airlock). The new Command Deck subsystems operate strictly behind authenticated session middleware.

## 3. Upstairs Mac mini Mirror (`src/server/mac-mirror.ts`)

The Upstairs Flight Director Office provides three interactive monitors, each bound to a `MacMirrorTargetId` (`copilot`, `claude`, or `desktop`):

1. **Left Desk Monitor (`copilot`):** Targets `GitHub Copilot` (`bundleId: com.github.Copilot`, process match `GitHub Copilot`).
2. **Right Desk Monitor (`claude`):** Targets `Claude Desktop` (`bundleId: com.anthropic.claudefordesktop`, process match `Claude`).
3. **South-Wall Ultrawide Monitor (`desktop`):** Targets the full Mac mini primary display (`screencapture -x -t jpg`).

### Window discovery and minimum backing-store check

When `/api/mac-mirror/frame?target=<id>` is requested with live capture enabled (`MOONBASE_MAC_MIRROR_LIVE=1`), `MacMirrorController` enumerates on-screen windows via CoreGraphics (`CGWindowListCopyWindowInfo(kCGWindowListOptionOnScreenOnly, kCGNullWindowID)`) to locate the largest visible window (`width > 200`, `height > 150`, `layer === 0`) belonging to the target application.

A subtle macOS behavior occurs when an application window is minimized, hidden behind another fullscreen space, or occluded: `screencapture -x -l <windowId>` can return a valid JPEG header containing an empty or solid-color backing store. To prevent the upstairs monitors from displaying blank white rectangles, `captureFrame` enforces a **`50 KB` minimum frame threshold** (`buf.length > 50_000`) for application windows (`15 KB` for full desktop captures). If the captured buffer falls below that threshold or macOS Screen Recording permission is unavailable, the server returns a high-contrast `1440x900` SVG status preview card with live process telemetry and a one-click **`Bring to Front on Mac mini`** action (`POST /api/mac-mirror/activate`).

### Remote input forwarding

The zoomed monitor modal (`src/client/ui/mac-mirror.ts`) supports two remote interaction primitives over `POST /api/mac-mirror/input`:

- **Normalized coordinate click forwarding (`type: "click"`):** The browser computes normalized coordinates `(x, y)` in `[0, 1]` across the rendered monitor surface. On the server, `sendInput` activates the target application via `osascript` and dispatches a CoreGraphics mouse event (`kCGEventLeftMouseDown` / `kCGEventLeftMouseUp`) or AppleScript click at the corresponding screen coordinates.
- **Keyboard text injection (`type: "text"` or `type: "key"`):** Text strings are sanitized and forwarded to the active application via `System Events` (`keystroke` and `key code` for `Enter`, `Tab`, `Escape`, and `Backspace`), enabling prompt entry and approval confirmation from a remote browser.

### Event-stream classification rules

`LiveSessionWatcher` reads only `workspace.yaml` metadata and the final `64 KB` tail of each `events.jsonl` (Copilot) or project `.jsonl` (Claude) file. It never writes to session directories, locks SQLite databases, or spawns CLI subprocesses:

- **GitHub Copilot sessions (`~/.copilot/session-state/<uuid>/`):**
  - Parses `workspace.yaml` for `summary`, `repository`, `branch`, and `cwd`.
  - Inspects the tail of `events.jsonl`. If the final events contain an unresolved `ask_user` or `exit_plan_mode` tool request, the session is marked `waiting`. If `ageMs <= 90_000` with active tool or turn execution (or `ageMs <= 25_000` mid-stream), it is marked `working`. Sessions updated within `15 minutes` are marked `idle`.
- **Claude sessions (`~/.claude/projects/<project>/<session>.jsonl`):**
  - Extracts the workspace slug, recent user prompt, assistant text snippet, and active `tool_use` blocks.
  - Marks the session `working` when modified within `45 seconds` (or `90 seconds` with an in-flight `tool_use` block) and `idle` up to `15 minutes`.
- **Deterministic desk binding:** Discovered sessions are sorted by state priority (`working` then `waiting` then `idle`) and recency (`updatedAt`), and the top six sessions are assigned `deskIndex: 0..5`. On the Three.js floor, each assigned desk spawns or updates a mini alien-dinosaur worker carrying a floating badge with the real session title, source (`Copilot` or `Claude`), and live activity dot. Clicking either the 3D dinosaur or its top-bar pill opens `src/client/ui/live-session-modal.ts` with the parsed transcript tail (`GET /api/live-sessions/:id/output`).

## 5. Spatial ergonomics, loft expansion, and First-Person View

The most visible usability failure of the earlier 3D room was spatial cramping in the upstairs office. In the original coordinate system, the Flight Director loft occupied only `8m x 5m` (`x: 10..18`, `z: 8..13`, `y: 3.0`, `height: 2.5m`). When the camera orbited behind the avatar in third-person mode, the loft's upper glass partition and banners intercepted the camera ray or filled the viewport.

### Loft coordinate expansion and automatic enclosure cutaway

In `src/shared/layout.ts` and `src/client/world/office.ts`, `LOFT` was expanded to a **`9.0m x 7.2m x 3.3m` elevated deck** (`x: 9.0..18.0`, `z: 5.8..13.0`, `y: 3.0`) with a centered `3.8m x 1.32m` executive workstation at `(13.5, 3.0, 10.15)`:

### Eye-level First-Person View and replacing the October `warlockHand` mesh

In `src/client/main.ts`, users can toggle First-Person View at any time via the **`1st Person`** button in the top-left Command Deck bar (`#deck-view-toggle`) or the `C` keyboard shortcut:

- **Camera placement and view switching:** Entering the upstairs office via **`goToUpstairsLoft()`** positions the player at `(13.5, LOFT.y, 7.75)` facing south (`camYaw = -Math.PI`, `lookPitch = -0.05`) and switches `player.setView('first')`, placing the camera at eye height inside the character with the viewmodel `handsGroup` attached to the camera.
- **Fixing the October seasonal hand bug (`src/client/world/hands.ts`):** The upstream Agent Office codebase contained a seasonal check (`const isOctober = new Date().getMonth() === 9`) that replaced the standard hand mesh throughout October with `warlockHand`, a procedural claw with green skin (`0x3a6b4c`) and long dark-red fingernails (`0x2a0a0a`). Because Moonbase characters are friendly alien dinosaurs, those zombie hands looked jarring and out of place. We removed the seasonal warlock branch entirely and replaced `handsGroup` with a custom sculpted dinosaur paw asset (`public/models/props/dino-paw.glb`), mirrored across left and right hands with idle breathing sway, walking bob, and click-tap animations.

## 6. Reproducible Blender asset pipeline and Virtual Rotating Photo Frame

All five new 3D assets introduced in the loft redesign are generated deterministically by versioned Python scripts executed under Blender (`4.2+`):

1. **Sculpted Dinosaur Paws (`scripts/blender/build_dino_hands.py` to `public/models/props/dino-paw.glb`, `182 KB`):**
   - Guided by a Higgsfield Soul 2.0 reference study of cute plush alien-dinosaur paws, the script constructs overlapping spheres and capsules for the rounded forearm cuff, plump palm, three stubby toes, and thumb, joins them into a unified mesh, and runs Blender's **Voxel Remesh** modifier (`voxel_size = 0.008`, `use_smooth_shade = True`) followed by a **Laplacian Smooth** pass (`iterations = 10`, `lambda_factor = 0.35`).
   - Separate rounded cream belly-pad, toe-bean, ivory claw, and dorsal pastel-spot meshes are attached and exported with roughness-tuned PBR materials (`DinoTealSkin` `#33C7B5`, `DinoCreamPad` `#FFF3D6`, `DinoCuteNail` `#FFF9EB`, `DinoSpotAccent` `#7BE8D8`).
2. **Flight Director Desk Hardware (`scripts/blender/build_desk_assets.py`):**
   - `mac-mini.glb`: Rounded silver aluminum unibody enclosure with dark front port strip and glowing cyan power LED.
   - `desk-keyboard-mouse.glb`: Low-profile dark mechanical keyboard with teal/purple accent keycaps and ergonomic wireless mouse on a desk mat.
   - `digital-photo-frame.glb`: Brushed-metal digital photo frame with an angled stand and a dedicated screen plane (`photoFrameScreen`) that receives dynamic `THREE.Texture` updates at runtime.
   - `desk-companion-kit.glb`: Studio headphone stand with over-ear headphones and a ceramic Moonbase coffee mug on a coaster.

### Virtual Rotating Photo Frame service (`src/server/photo-frame.ts`)

The digital photo frame on the right wing of the Flight Director desk is backed by `PhotoFrameController`:

- **Three photo sources (`builtin`, `folder`, and `upload`):** Users can point the frame at any local folder on the Mac mini (`POST /api/photo-frame/config` with `folderPath`, plus auto-discovered `suggestedFolders` like `~/Pictures` and `~/Desktop`), upload a folder of images directly from a remote browser (`POST /api/photo-frame/upload`), or use the built-in Lunar Base gallery (`source: 'builtin'`). Rotation interval (`intervalSec`, `3..300s`) and `shuffle` are persisted across restarts.
- **Image serving with traversal protection (`GET /api/photo-frame/image?id=<id>`):** Resolves the requested slide by validated item ID and restricts file extensions to `.jpg`, `.jpeg`, `.png`, `.webp`, `.gif`, `.avif`, and `.svg` inside the configured directory.
- **Built-in Lunar Base gallery:** Out of the box, `BUILTIN_SLIDES` provides four resolution-independent SVG illustrations (`earthrise-observatory.svg`, `dino-crew-portrait.svg`, `upstairs-command-blueprint.svg`, `lunar-greenhouse-sunset.svg`) so both the 3D desk frame and the full-screen modal (`src/client/ui/photo-frame.ts`) work immediately with zero configuration.
